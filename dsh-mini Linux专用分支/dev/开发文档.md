## 1. 项目定位（Linux 专用分支当前形态）

* **单文件 Python 源码**：`dev/dsh-mini.py`（约 7,800 行），只用 Python 标准库，无外部强制网络依赖，面向 **Python 3.8 ~ 3.14+**。
* **单文件且双击即开**：
  * 打包产物为 Linux x86_64 原生单文件 ELF 可执行二进制 `dsh-mini`（约 14MB，内置 Python 运行时与完整 GUI，目标机器零前置依赖）；
  * 配合桌面启动图标 `dsh-mini.desktop` 与启动脚本 `start-dsh-mini.sh`，在 Linux 桌面环境下实现**双击直接弹出图形窗口**。
* **唯一主界面为原生图形界面**：
  * Linux 平台下使用 **Tkinter** 原生实现（`DshTkGui`），无控制台黑框；Windows 下保留 Win32 Edit 实现，实现 100% 界面与功能对齐；
  * 具备完整菜单栏（会话、工具、设置、帮助）、对话区流式渲染（区分思考过程 `…` 与正文 `●`）、Token 消耗与缓存统计、自增高多行输入框、状态栏。
* **面向 AI 自主调用的五大工具集**：
  1. `pwsh / bash` —— 持久化 Shell 命令执行（Linux 下默认使用 Bash，`cd` 目录、环境变量、函数跨多轮对话长驻）；
  2. `str_replace_editor` —— 文件查看/创建/编辑（支持 Linux `/` 绝对路径规范）；
  3. `mouse_control` —— 鼠标自主操作（移动、点击、双击、长按、释放、滚轮、坐标与分辨率查询，集成 Linux `xdotool`）；
  4. `read_image` —— AI 自行读取本地图片编码为 Base64 Data URL 送入多模态上下文进行视觉分析；
  5. `take_screenshot` —— AI 自行截取桌面屏幕送入多模态视觉上下文（集成 Linux 原生截图工具链 `scrot` / `gnome-screenshot` / `grim`）。
* **接口支持**：支持 OpenAI 兼容 `/chat/completions`（流式/非流式），原生支持 OpenAI Vision 视觉格式。

## 3. Linux 环境搭建与一键打包

### 3.1 环境要求
* 操作系统：Ubuntu 20.04/22.04/24.04/26.04、Debian 11/12 或主流 Linux 发行版（x86_64）；
* Python 运行时：Python 3.8 ~ 3.14+；
* 系统工具包（打包与自动化测试推荐）：
  ```bash
  sudo apt update
  sudo apt install -y python3-tk python3-pip xdotool scrot xvfb
  ```

### 3.2 一键构建与自检
在 `dev/` 目录下运行 `build-linux.sh`：
```bash
cd dev
bash build-linux.sh
```

脚本将自动执行完整流水线：
1. 检测 Python 3 与 `pyinstaller`（若未安装会自动安装）；
2. 使用 `dsh-mini-linux.spec` 通过 PyInstaller `--clean` 编译出单文件二进制 `../dsh-mini`；
3. 自动授予 `chmod +x` 执行权限；
4. 调用新生成的单文件二进制自动运行 **92 项离线自检**（`../dsh-mini --selftest`）；
5. 92 项测试全通过后提示构建完成。

## 5. Shell 工具协议（pwsh / bash 持久会话）

### 5.1 设计目标
在没有控制台或后台无交互环境下，执行 AI 下发的系统命令。要求：
1. **状态保持**：多次命令之间保持当前工作目录（`cd`）、环境变量（`export`）、定义的函数；
2. **精确分界**：准确界定某条命令的输出边界与返回退出码；
3. **安全与鲁棒**：支持命令超时打断、会话崩溃自动拉起、失败自动降级为单命令模式，绝不挂死。

### 5.2 Linux Bash 持久会话实现（`BASH_LOADER_TEMPLATE`）
在 Linux 下，`PersistentShell` 启动后台进程：
```bash
/bin/bash --norc -c "<BASH_LOADER_TEMPLATE>"
```
协议运行原理：
1. **命令打包**：父进程将待执行的命令转换为一行协议文本：前缀字符 `@`，命令内部所有换行用 ASCII 控制字符 `\x1e`（Record Separator）占位，末尾补换行 `\n`。
2. **行缓冲读取**：Loader 在循环中使用 `IFS= read -r __dsh_line` 逐行接收，自动去除末尾可能残留的 `\r`；
3. **命令还原与执行**：将 `\x1e` 还原为标准换行 `\n`，输出开始标记 `__DSHMINI_<tag>_BEGIN__`，随后调用 `eval "$__dsh_cmd"` 执行；
4. **状态捕获与返回**：执行完毕捕获 `$?` 状态码，输出结束标记 `__DSHMINI_<tag>_END:<exitcode>`；
5. **父进程异步监控**：读取线程按 tag 匹配收集输出，`threading.Event` 通知同步返回。

### 5.3 故障降级机制
* 若持久会话启动超时或握手失败，会自动切换到 `oneshot` 单命令模式（每条命令单独 `subprocess.Popen([exe, "-c", cmd])` 运行）；
* 降级后系统提示词会自动注入说明，通知大模型"当前处于单命令模式，目录与变量不保持"，保证 AI 认知与实际行为一致。

## 6. GUI 线程模型与多模态交互

### 6.1 线程模型
* **UI 主线程**：唯一负责驱动 Tkinter 的 `root.mainloop()` 窗口绘制与系统事件分发。
* **Agent 工作线程**：每轮用户发送提问或 AI 执行长耗时命令时，在独立的守护线程中运行（`threading.Thread(target=self._worker)`），保证界面始终丝滑、不卡顿。
* **跨线程通信（无锁队列）**：
  * 工作线程将流式输出、状态变更、工具开始/结束事件打入 `queue.Queue`；
  * UI 主线程通过 `self.root.after(50, self._drain)` 定时轮询排空队列并追加渲染到 `Text` 控件中。
* **用户打断机制**：按 `Esc` 键或点击界面「停止」按钮时，主线程触发 `self.cancel_event.set()` 并调用 `self.shell.kill()` 强杀子进程，工作线程感知后立即优雅收尾。

### 6.2 模态对话框系统
`_GuiInputDialog`（单行输入框）与 `_GuiChoiceDialog`（列表选择框）采用 Tkinter `Toplevel` 实现模态弹窗：
* `top.transient(root)` + `top.grab_set()` 保证焦点锁定；
* 弹窗在呼出时根据父窗口屏幕绝对坐标计算居中位置（`rx + (rw - width)//2`），无论多显示器或缩放比例均完美居中；
* 支持 `Enter` 确认、`Esc` 取消、`Tab` 切焦。

## 8. 核心踩坑清单与避坑指南（关键资产）

以下问题均是在 Linux 移植与实测过程中定位并修复的关键缺陷，后续修改切勿重蹈覆辙：

1. **GNOME GIO 默认拦截二进制双击**：
   * *现象*：直接在 GNOME Nautilus 中双击 ELF 二进制无法运行（被判定为安全策略拦截）；
   * *解决*：提供配对的 `dsh-mini.desktop` 文件并赋予 `+x` 权限，桌面通过 `gio launch` 或双击 Desktop 图标无障碍直起。
2. **Desktop 文件 Exec 字段中的空格路径**：
   * *现象*：路径包含中文或空格时（如 `dsh-mini Linux专用分支`），使用反斜杠转义会导致 `gio launch` 解析失败；
   * *解决*：Exec 项必须使用标准双引号包裹整个路径：`Exec="/完整路径/dsh-mini"`。
3. **PowerShell 管道与 Bash stdin 的 CRLF 污染**：
   * *现象*：Windows 传入的脚本常带有 `\r\n`，Bash 的 `read -r` 会将 `\r` 视作命令内容的一部分导致找不到命令；
   * *解决*：在 Loader 头部显式加入 `__dsh_line="${__dsh_line%$'\r'}"` 剥离回车符。
4. **Linux 缺少 GBK 本地代码页导致解码测试失败**：
   * *现象*：Linux 系统默认 locale 仅为 UTF-8，`candidate_output_encodings()` 若未将 GBK 显式加入候选列表，读取历史 GBK 文件时会抛出 UnicodeDecodeError；
   * *解决*：在解码回退链中无条件包含 `gbk`, `cp936`, `gb18030`。
5. **模态弹窗参数签名的多样性**：
   * *现象*：`_GuiInputDialog.ask` 在多处调用中存在位置参数与关键字参数混用的情况；
   * *解决*：Tkinter 适配层采用通用参数打包解析（`*args, **kwargs`），全面兼容各种调用方式。
6. **KV Cache 前缀失配（思考模型长对话越跑越慢）**：
   * *现象*：思考模型多轮对话时首 Token 延迟高达数十秒甚至数分钟；
   * *解决*：在 `Agent.run_turn` 组装 `history_message` 时必须原样保留助手的 `reasoning_content`，并在 `format_usage` 中兼容 llama.cpp / OpenAI 的 `prompt_tokens_details.cached_tokens`。
