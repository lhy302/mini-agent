> 本文档面向"要继续开发或维护这个程序"的读者。读完应该能：

## 1. 项目定位（当前形态）

* **核心价值定位**：
  1. **零门槛种子引导 Agent（Seed / Bootstrapper Agent）**：专为完全未安装 Agent、没有任何开发环境的纯净 Windows 10/Win11 机器设计。由于它是单文件且零外部依赖，用户双击即开，可通过向 AI 下达自然语言指令（如“在这台机器上帮我安装 Node.js、Git 并部署 DSH 完整版”），由本程序自主调用 Shell 命令和文件编辑，自动为用户安装并配置好重量级 Agent。
  2. **轻量即开即用 Agent**：在无需安装庞大重量级 Agent 或临时使用场景下，提供极简、低资源占用、原生 Win32 图形界面的本地 Agent 辅助能力。
* 单文件 Python 程序 `dsh-mini.py`，只用标准库，面向现代 **Python 3.8 ~ 3.14+**。
* 唯一界面是**图形界面**（纯 ctypes + Win32 控件，无控制台黑框）；打包后是无控制台的 `dsh-mini.exe`。
* 工具集（全部面向 AI 自主调用，用户只需对 AI 下达目标）：
  * `pwsh` —— PowerShell 命令执行（执行静默安装包、配置系统环境、运行脚本）
  * `str_replace_editor` —— 文件查看/创建/替换/插入（改写与生成配置文件）
  * `mouse_control` —— 鼠标自主控制（移动放到哪、点击哪、左键/右键/中键/双击/长按/滚轮）
  * `read_image` —— AI 自行读取本地图片并送入多模态上下文进行视觉分析
  * `take_screenshot` —— AI 自行截取 Windows 屏幕并送入多模态上下文进行视觉分析
* 接口：支持 OpenAI 兼容 `/chat/completions`（流式/非流式），支持 OpenAI 视觉多模态协议。
* 目标环境：Windows 10 / Windows 11（64 位），已彻底剥离旧版 Win7 历史兼容包袱。

## 3. 环境搭建（打包机）

1. 安装 Python 3.8.10（64 位），**装到无中文、无空格的路径**，例如 `C:\py38`。
   （仅当前用户安装即可，不需要管理员；`build-win7-exe.bat` 会依次找
   `%LOCALAPPDATA%\Programs\Python\Python38`、`%USERPROFILE%\py38`、`C:\Python38` 等常见位置）
2. 安装打包器（6.x 已放弃 Win7 / Py3.8，必须 5.x）：

```bat
C:\py38\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple pyinstaller==5.13.2
```

3. 打包：`dev\build-win7-exe.bat`（或手动）：

```bat
C:\py38\python.exe -m PyInstaller --noconfirm --clean --distpath .. --workpath build dev\dsh-mini.spec
```

要点：
* spec 里 `console=False` —— 产物是无控制台的 GUI。
* spec 会从打包机 `C:\Windows\System32\downlevel` 收集 `api-ms-win-crt-*.dll` + `ucrtbase.dll`，
  外加 Python 目录的 `vcruntime140.dll` / `vcruntime140_1.dll` / `python3.dll`。
  **这是"拷到干净 Win7 也能跑"的关键，别删。**
* 版本号改三处（见 §11）。

## 6. pwsh 工具协议（最重要的资产，改动前先读完）

目标：在任意 Windows（Win7 + PowerShell 2.0 ~ Win11 + PowerShell 7）上可靠地执行命令，
尽量保持会话状态（变量/当前目录），失败要**可降级、可诊断、永不无声卡死**。

### 6.1 候选与探测

* `powershell_candidates()` 按优先级列候选：`shell_exe` 配置 → PATH 里的 pwsh →
  `System32\WindowsPowerShell\v1.0\powershell.exe` → 32 位版本 → PATH 里的 powershell。
  **不存在**的绝对路径会被跳过；如果用户配了 `shell_exe` 但没被用上，要明确提示。
* `check_powershell()` 对每个候选实跑一条探针（结果按 shell_exe 缓存）：

```
DSHMINI_PROBE_OK ps=<版本> cn=中文探测正常
```

探针里带中文，是为了**校验编码链路**（stdin/参数/解码整条链）。探针不通 → 换下一个候选。

### 6.2 持久会话（persistent，默认优先）

* 启动：`<exe> -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command <loader>`
  * loader 源码在 `PS_LOADER_TEMPLATE`，**只用 PowerShell 2.0 就有的语法**（兼容 Win7）；
  * loader 自己 `while($true)` 循环读 stdin（`StreamReader(UTF8, OpenStandardInput)`），
    只处理以 `@` 开头的行；
  * 命令体：**UTF-8 纯文本**（不是 base64！见 §9），多行用 `\x1e`（char 30）占位，
    loader 端 `.Replace([char]30, [char]10)` 还原；
  * 执行用 `Invoke-Expression`，终止性错误被 catch 后以 `ERROR: <msg>` 打到 stdout；
  * 每条命令的输出用标记包裹：`__DSHMINI_<tag>_BEGIN__` … `__DSHMINI_<tag>_END:<exitcode>`，
    标记由 `DshGui`/父进程按行匹配；**标记一律 `[Console]::Out.WriteLine + Flush`**，
    不依赖宿主缓冲策略；
  * 退出码：`$global:LASTEXITCODE` 优先，其次 `catch` 置 1。
* 父进程（`PersistentShell`）：
  * 读线程逐行解码（`decode_output`：UTF-8 优先，回退本机 ACP/OEM，选替换字符最少的）；
  * `run()` 持锁串行发送；超时（`shell_timeout_ms`）杀进程并返回
    `SHELL_RESET_MESSAGE`；进程死亡返回 dead 状态；
  * **握手**：启动后先发探针，`shell_probe_timeout_ms`（默认 20s）内拿到
    `DSHMINI_PROBE_OK` **且** 中文回环一致才算成功；
  * **降级**：握手失败 / 会话中途死亡 → `shell_mode` 切到 oneshot，
    给用户一条中文提示（`on_notice`），给模型一条 `[shell note]`（只发一次），
    同时 `describe()` 改写系统提示词里的说明（"状态不跨调用保留"）。

### 6.3 单命令模式（oneshot，兜底）

* `<exe> -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command <script>`
  * `script = ONESHOT_PREAMBLE + 用户命令 + ONESHOT_TAIL`
    （前导压掉进度条/设编码；收尾把 `$global:LASTEXITCODE`/`$?` 换算成 `exit N`）；
  * 长度 > `ONESHOT_INLINE_LIMIT`(8000) → 写临时 `.ps1`（utf-8-sig）用 `-File` 跑，
    **不用** `-EncodedCommand`（它会把错误流序列化成 CLIXML 垃圾），
    **也不读文件再 Invoke-Expression**（无文件执行特征，容易被杀软误报）；
* 状态不保持（每条命令一个进程），`cwd` 由 Popen 的工作目录兜底；
* 超时杀进程，返回 `SHELL_ONESHOT_MESSAGE`。

### 6.4 进程创建参数

`_proc_flags()` = `CREATE_NEW_PROCESS_GROUP`；**父进程无控制台（GUI）时再加
`CREATE_NO_WINDOW`** —— 给子 PowerShell 一个自己的隐藏控制台：不闪黑框、
不干扰父进程控制台状态。环境变量注入 `PYTHONIOENCODING/PYTHONUNBUFFERED/DSHMINI_SHELL`。

### 6.5 对外行为约定（改动时保持）

* `PersistentShell.run()` 返回 `(输出文本, 退出码或 None, 附加说明)`；
* `run_pwsh_tool()` 负责截断（`max_output_chars` + `TRUNCATED_SHELL`）、
  拼 `[exit code: N]` 与说明；Agent 把异常文本也当作工具结果回传给模型；
* 自检（`run_shellcheck`）判据**不要绑死英文措辞**：PowerShell 报错文案随 UI 语言变
  （中文系统是"找不到路径"），用路径/关键字/退出码做判据。

## 7. 缓存（token 花费）

DeepSeek 系接口有**自动前缀缓存**（命中部分约 1/10 价），无需任何请求参数。
生效条件：请求前缀逐字节一致。本项目为此保证：

1. `Agent` 的 `messages` **只追加，不改写**；
2. system prompt 每轮重算但内容稳定，`_refresh_system_prompt()` 内容不变就不赋值；
3. tools schema 固定；
4. `include_usage` 默认 true，usage 里的 `prompt_cache_hit_tokens / prompt_cache_miss_tokens`
   会在界面显示（`format_usage`），用于核实命中。

会必然导致 miss 的操作：换模型、改 system_prompt 措辞、改 tools、
在消息前部插入任何随时间变化的文本（时间戳等）—— 都不要做。


## 8. GUI 架构（纯 ctypes + Win32）

没有引入任何 GUI 库（不用 tkinter：PyInstaller/嵌入式 Python 里它是个麻烦）。
三个窗口类共用一个消息循环（都在主线程创建）：

| 类 | 角色 |
|---|---|
| `DshGui` | 主窗（`DshMiniGuiWnd`）：菜单栏、对话区（只读 EDIT）、输入框（多行 EDIT）、发送按钮、状态栏 |
| `_DiagWindow` | 诊断/自检的独立窗口（`DshMiniDiagWnd`），输出另存 `dsh-mini-diagnose.txt` |
| `_GuiChoiceDialog` | 通用"列表 + 手输"选择框（`DshMiniChoiceDlg`），用于模型选择与会话切换 |
| `_GuiInputDialog` | 单行输入框（`DshMiniInputDlg`），设置接口地址/密钥/模型（三连弹） |

### 8.1 线程模型（必须遵守）

* **主线程**：跑消息循环（`DshGui.run`），是唯一允许碰控件/调用 Win32 UI API 的线程；
* **worker 线程**：每轮对话一个（`_worker`），诊断/模型扫描也各有线程；
* worker 与主线程只通过 `queue.Queue` 通信：`push()` / `set_status()` 入队，
  主窗 `WM_TIMER`（120ms）里 `_drain()` 出队并更新 EDIT；
* worker 结束时 `PostMessageW(WM_APP_DONE)` 通知主线程收尾（恢复发送按钮等）。
  **不要在 worker 里直接 SetWindowText / MessageBox。**

自定义消息：`WM_APP_DONE=0x8001`、`WM_APP_PICKER=0x8002`、`WM_APP_DIAG=0x8003`；
定时器：`TIMER_ID=1`（drain）、`TIMER_ID+1`（autoclose，冒烟测试用）、
`TIMER_ID+2`（启动动作：命令行参数翻译过来的动作 / 启动时选模型）。

### 8.2 控件 ID 与菜单 ID

控件：output=1001、input=1002、send=1003、status=1010。
菜单：会话 2001 新对话 / 2005 打开会话 / 2002 保存 / 2003 复制 / 2004 退出；
工具 2101 自检 / 2102 诊断 / 2103 打开诊断日志 / 2104 界面日志 / 2105 清空；
设置 2201 模型 / 2202 接口与密钥 / 2203 工作目录；帮助 2301 指南 / 2302 关于。

### 8.3 输入框（子类化）

输入与输出两个 EDIT 都被 `SetWindowLongPtrW(GWLP_WNDPROC)` 子类化，
按键统一走 `_handle_key`（完整键位表见 README"快捷键"一节）：

* `Enter` 发送（**多行 EDIT 里必须自己处理，否则回车会被吃掉**）；
* `Ctrl+J` / `Shift+Enter` 换行（`EM_REPLACESEL`）；
* `↑/↓` 历史输入（单行时接管，多行时放行给系统光标移动）；
* `Esc` 打断（`cancel_event.set()` + `shell.kill()`）；
* `Ctrl+C` 有选中走系统复制，没选中清输入，空输入再按退出；
* `Ctrl+D` 退出、`Ctrl+L` 新对话、`Ctrl+S` 保存、`Ctrl+O` 打开会话、`F1..F8` 功能键。

输入框随内容自动增高（`_autogrow_input` → `EM_GETLINECOUNT` → `_layout`）。

### 8.3.1 弹出式对话框（输入框 / 选择框 / 诊断窗）的六条纪律

自己搭的窗口没有对话框管理器，下面每一条都对应一次真实事故（见 §9.12）：

1. **窗口类只注册一次**：`gui_register_window_class()` 按类名缓存，
   同名第二次直接返回第一次的回调。窗口过程对象存在模块级字典里常驻 ——
   被 GC 掉就是注册表里的野指针。
2. **状态按 hwnd 存，不用闭包**：`_states = {hwnd: state}`，
   CreateWindowExW 还没返回时用 `_creating` 兜底（WM_NCCREATE/WM_CREATE 期间）。
3. **弹出后必须 `SetFocus(编辑框)`**：顶层窗口拿到焦点不等于里面的 EDIT 拿到焦点。
   实测 `GetGUIThreadInfo().hwndFocus` 会等于对话框本身，键盘输入全丢。
   顺带 `SetActiveWindow` + `EM_SETSEL(0,-1)`（全选原值，直接打字就覆盖）。
4. **消息循环要学会退出**：`GetMessage` 只在 WM_QUIT 时返回 0，
   `DestroyWindow(dlg)` 之后它照样一直等消息。所以 `gui_run_modal()` 每轮检查
   `done` / `IsWindow(dlg)`，关窗时再 `gui_wake_message_loop()` 塞一条 WM_NULL
   把它立刻叫醒。**不这么写，点"确定"就等于没点**。
5. **模态 = 禁用属主窗口**：`EnableWindow(owner, False)`，关掉后再恢复并把焦点
   还给弹框前的那个控件。否则主窗照样收消息，能在第一个框还开着的时候再按 F2，
   把 `_on_setup` 叠进第二层消息循环（实测叠过三层）。
6. **键盘热键在 dispatch 之前截**：Enter=确定、Esc=取消、Tab 轮转焦点。
   注意消息字段名是 `msg.hWnd`（大写 W），写 `msg.hwnd` 会 AttributeError。
   热键/焦点逻辑整体套 try/except 并写崩溃日志，异常不能让对话框变孤儿。

两个对话框的控件 ID **不一样**（写自动化脚本时容易踩）：

| 对话框 | 类名 | 编辑框 | 标签 | 列表 | 确定 | 取消 | 其它 |
|---|---|---|---|---|---|---|---|
| 输入框 | `DshMiniInputDlg` | 1 | 2 | — | 3 | 4 | 5=显示密钥 |
| 选择框 | `DshMiniChoiceDlg` | 53 | 51 | 52 | 54 | 55 | — |
| 诊断窗 | `DshMiniDiagWnd` | 41 | — | — | — | 45=关闭 | 42 复制 / 43 另存 / 44 清空 |

### 8.4 输出排版（踩过坑）

* **Windows EDIT 控件只认 CRLF**：所有进 UI 的文本统一转成 `\r\n`
  （`DshGui.push` 里做）。只写 `\n` = 换行直接消失（v1.1.0 之前的"没有回车"）。
* 块与块之间显式空行：`GuiEmitter._end_block()`；模型流式输出结束也要收尾
  （`_worker` finally 里 `_end_block()`），否则下一段会粘在同一行。
* `push_line()`：整行类输出（命令结果、提示）在"当前不在行首"时先补 `\n`。
* 日志文件以 `newline=""` 打开：文本模式默认会把 `\n` 翻译成 `\r\n`，
 叠加我们自己写的 CRLF 会变成 CRCRLF（日志里多出空行）。

### 8.5 ctypes 陷阱

* **所有**用到的 user32/gdi32 函数都要声明 `argtypes/restype`：
  64 位下 `LPARAM/WPARAM` 是 64 位，不声明会被当 32 位截断，
  `DefWindowProcW` 会 `OverflowError: int too long to convert`，
  `CallWindowProcW` 直接访问违例。
* `WNDPROC` 回调用 `ctypes.WINFUNCTYPE(c_ssize_t, HWND, c_uint, WPARAM, LPARAM)`，
  **引用必须保存在实例属性上**（否则 GC 掉就崩）。
* `SetWindowLongPtrW` 只有 64 位有；32 位构建要用 `SetWindowLongW`（当前只出 64 位）。
* 结构体：`_wndclassex(ctypes, wintypes)` 返回 `WNDCLASSEXW` 类，三个小窗口共用。

### 8.6 无控制台（windowed）打包的行为

* `sys.stdout is None`：`print` 是 no-op，任何"必须被看见"的输出要走 GUI 或
  `_message_box`；`install_safe_streams` / `fix_stdio_encoding` 都对 None 安全。
* `main()`：`args.gui or headless_build` → 把 `--selftest/--shellcheck/--setup/-p/--models`
  翻译成 `startup_action`，窗口起来 700ms 后由 `_run_startup()` 执行。
* `--gui-autoclose N`：冒烟测试模式 —— 开窗、自动跑一次 pwsh 诊断、N 秒后自毁，
  退出码 0 = 正常。**自动化测试全靠它**（不需要人点鼠标）。

## 9. 坑清单（真实踩过，别踩回去）

1. **Win7 控制台 cp936 严格编码**：往 stdout 写 GBK 表示不了的字符
   （`»` U+00BB、`›` U+203A）会 `UnicodeEncodeError` 直接崩。GUI 时代不再写控制台，
   但 `SafeStream/console_safe` 保留（万一有人用控制台跑源码）。
2. **`-EncodedCommand` 会把错误流序列化成 CLIXML**（`#< CLIXML ...<Objs ...`），
   输出没法读 → 一律用 `-Command`。
3. **`-Command` 命令行长度上限**（约 32K）：超长命令走临时 `.ps1` + `-File`。
4. **PowerShell 报错文案随 UI 语言变**：自检判据别绑英文（"Cannot find path" vs
   "找不到路径"）。
5. **PowerShell 2.0 语法限制**：loader 与 oneshot 脚本只用 V2 就有的语法；
   `$x = if(...){}` 这种在 V2 反而可以，但 `-LiteralPath`、三元、`??` 之类别用。
6. **PyInstaller onefile 有父子两个进程**：窗口属于子进程。
   自动化测试找窗口按**类名**全局找，别按 launcher PID 过滤。
7. **`Get-Process(launcher).MainWindowHandle` 恒为 0**（同上），别用它判断窗口。
8. **EDIT 控件 CRLF / 日志 newline=""**：见 §8.4。
9. **前缀缓存**：system prompt 字节级稳定、消息只追加（见 §7）。
10. **杀软启发式**：不做 base64 解码执行、不做读文件动态执行、写正规版本资源；
    PyInstaller onefile 的 `Trojan:Win32/Bearfoos.A!ml` 判定是误报。
11. **诊断输出不要写进对话区**（用户明确要求）：自检/诊断一律进独立窗口 +
    `dsh-mini-diagnose.txt`。
12. **自己搭的对话框三连坑（v1.1.3，"密钥填不进去"的元凶）**，细节见 §8.3.1：
    ① 弹窗后没 `SetFocus` 到编辑框 → 键盘输入落在顶层窗口上，一个字符都进不去；
    ② 每次弹框都重复 `RegisterClassExW` 同名类 → 第二次起沿用第一次的窗口过程，
       标签串台、填的值写进作废的返回值；
    ③ `DestroyWindow` 不会让 `GetMessage` 返回 → 点"确定"后 `ask()` 永不返回，
       `_on_setup` 永远走不到保存配置（表现："填完点确定什么都没发生"）。
    验证手段：`dev\gui-e2e.py`（26 项断言）。
13. **`ctypes.wintypes.MSG` 的字段是 `hWnd`**（大写 W），不是 `hwnd`；
    而且**不要随手给 user32 函数加 `argtypes`**：`LoadCursorW` 第二个参数是
    `MAKEINTRESOURCE` 整数（声明成 `LPCWSTR` 后传 32512 直接 TypeError，
    程序一启动就崩）。加声明前先确认所有调用点的参数类型。
14. **跨进程读/写别人的控件不可靠**：`GetWindowText` 对别的进程的控件不送
    `WM_GETTEXT`，`SetWindowText` 也可能被"缓存"截胡；`EM_REPLACESEL` 这类
    带指针的消息跨进程更是指针失效。写自动化测试时，判据要落在**文件/日志**
    这种进程外可见的结果上；想模拟打字就 `PostMessage(WM_CHAR)` 到**有焦点的**
    控件（没焦点的 EDIT 会直接丢掉 WM_CHAR）。
15. **`self.XXX` 常量漏定义 = 快捷键全灭（v1.1.2~v1.1.3 一直存在）**：
    `_handle_key` 第一行就是 `if key == self.VK_ESCAPE:`，而 `DshGui` 里
    **从来没有定义过 VK_ESCAPE**。窗口过程是 ctypes 回调，异常只打到 stderr
    （windowed 打包后没人看得见），键就被静静吃掉 —— 于是**回车发送、Esc 打断、
    F1..F8、Ctrl+L/S/D/O、↑↓ 翻历史全部失效**，用户只能用鼠标点按钮。
    两层防护：`dev\check-constants.py` 按类静态检查（改动后必跑），
    以及 `_safe_key()` 把快捷键异常兜住并写 `dsh-mini-error.log`。
16. **输出视图"对齐上边缘"的三种死法**（同一个窗口、139 行、视口 28 行实测）：

    | 写法 | 结果 |
    |---|---|
    | `SetWindowTextW` 整体重设 + `EM_SETSEL(-1,-1)` + `EM_SCROLLCARET` | first=0 → 停在**最上面**（`wParam=-1` 是"取消选择"，不是"移到末尾"，插入点还在开头） |
    | 插入点末尾 + `SB_BOTTOM` | first=138 → **滚过头**，末行被顶到视口顶端、下面 27 行空白 |
    | 插入点末尾 + `EM_SCROLLCARET` | first=111（≈差 6 行，SCROLLCARET 比实际视口保守） |
    | **`EM_LINESCROLL(0, 总行数-可见行数-首行)`** | first=111 == 理想值 ✓ **贴下边缘** |

    正解＝**只追加新内容**（`EM_REPLACESEL`，不要整体重设）+ 按
    `OUTPUT_LINE_HEIGHT`(20px) 算可见行数 + 精确 `EM_LINESCROLL`。
17. **写自动化测试必须先 `SetProcessDPIAware()`**：应用是 DPI-aware 的，
    测试进程不声明就会拿到被系统虚化的尺寸（实测 574px 的真实客户区被报成
    459px），据此算"可见行数"会得出完全错误的结论（我被这个坑了半轮）。
18. **client 会缓存 base_url/api_key**：`OpenAICompletionsClient` 在构造时把它们
    存进实例，F2 改了配置后如果只更新 `client.config`，请求里带的还是旧值
    （用户表现："填了新密钥却还是报鉴权失败，重启才好"）。改配置一律走
    `client.reload(config)`。
19. **模态对话框躲到别的窗口后面 = 整个程序"看起来死了"（v1.1.5）**：
    模态期间主窗会被 `EnableWindow(owner, False)` 禁用（正确），但如果对话框没能
    抢到前台（**本进程不在前台时系统会拒绝 `SetForegroundWindow`**），它就可能
    被浏览器等窗口盖住。此时用户看到的是：主窗点不动、**连标题栏 ✕ 都没反应**、
    光标还停在 I 型上（禁用窗口不更新光标形状）—— 判定"程序卡死"，其实程序活得好好的
    （实测：线程响应正常、无鼠标捕获、无菜单/移动循环、对话框可见且在前台）。
    五条修法（缺一不可，见 §8.3.1）：
    * 弹出时 `SetWindowPos(HWND_TOPMOST)` 强制置顶（**不依赖前台权限**），关闭时撤掉；
    * 窗口类补 `hCursor`（否则光标停在对话框空白处会一直保持上一个形状 = I 型）；
    * `WM_ACTIVATE` 里重新 `SetFocus(主要控件)`（激活是异步到的，会把焦点顶掉）；
    * 关窗后 `PostMessage(owner, WM_APP_REFOCUS)`，在激活尘埃落定之后把焦点交回输入框
      （否则焦点可能落在一个**已销毁的控件**上，表现为"打字毫无反应"）；
    * 模态期间把主窗标题改成"… —— 请先完成弹出的对话框"，结束还原 —— 万一对框
      真被挡住了，用户也知道要找什么。
    排查这类问题的正确姿势：**趁卡住时抓现场**（`GetGUIThreadInfo` 的
    active/focus/capture/menuOwner/moveSize + `WindowFromPoint` + 逐层 `IsWindowEnabled`
    + `SendMessageTimeout(WM_NULL)` 判响应），不要靠猜（见 §14）。

## 12. 已知限制 / 待办

* 只支持 OpenAI Chat Completions（无 Responses/Anthropic 协议）；
* 无上下文自动压缩：超长对话靠「新对话」+ 会话文件；
* 单命令模式没有实时输出（结果一次性返回）；持久会话才有逐行实时输出；
* GUI 主题/字号写死（微软雅黑），未做暗色模式；对话框坐标也是固定像素，
  高 DPI（150% 缩放）下会显得偏小；
* 自检/诊断窗口是模式无关的顶层窗，一次一个实例；
* 设置流程是"两个框依次弹 + 自动接模型列表"：没法只改其中一项而不点前一项的确定，
  以后可以改成一个窗口里放两行 + 密钥打码；
* 输出区**始终跟随末尾**（一边流一边自动贴底）：想往上翻历史得等这一轮结束。
  改进方向：用户往上翻时暂停自动跟随，翻回底部再恢复；
* 打包只出 64 位（Win7 32 位机器跑不了；需要时用 32 位 Python 3.8 重打）。

## 13. 脱敏（公开包发布前必查）

公开目录 = `dsh-mini\`（源码 + exe + 文档）。**用户私有副本（带真实配置和会话的目录）
永远不进公开包**。扫描思路（命中即修）——按类别列，不要把真实值写进任何文档：

```
API 密钥格式               sk- 开头的长随机串
配置里有值的 api_key        只允许空串或明显的占位符
私人网关 / 测试端点          IP、内网域名、第三方测试站
用户名 / 私有路径            Windows 用户名、含人名的路径
私有目录名                  自己起名的部署目录
测试残留                    sessions\、*.log、diagnose 文件
```

同时检查：`sessions\` 不在公开目录；`dsh-mini-gui.log` / `dsh-mini-diagnose.txt` /
`dsh-mini-error.log` 不在公开目录；`dev\build*` / `__pycache__` 已删
（PyInstaller 的 TOC/xref 里含打包机绝对路径）。

## 14. 给 AI / 自动化工具的额外提醒

* 本项目的"现象描述"经常和真实根因差一层（Win7 的锅常被记在程序头上）：
  先看日志（`dsh-mini-gui.log` / `dsh-mini-diagnose.txt` / `dsh-mini-error.log`），
  再下结论；用户截图可以用 Windows OCR（`Windows.Media.Ocr`）转文字。
* 改动后必须跑：`python dev\check-constants.py`（静态查漏定义的常量）→
  `--selftest`（81 项）→ `--gui-autoclose` 冒烟 → `python dev\gui-e2e.py`（48 项，假网关）
  → `python dev\real-api-test.py`（真实接口一条）。打包后再对 exe 各跑一遍。
* **UI 类问题要"趁卡住时抓现场"**：`GetGUIThreadInfo`（active/focus/capture/menuOwner/
  moveSize）、`WindowFromPoint`（谁在指针下）、逐层 `IsWindowEnabled`、
  `SendMessageTimeout(WM_NULL)`（线程还响不响应）、`GetCursorInfo`（光标形状）。
  这些只读查询不会打扰用户，比反复推测有效得多 —— v1.1.5 那个"整个程序死了"就是这么定的性。
* 输出长文本时分段写（一次性超长输出会被掐断）。
* 与用户沟通用中文；文档、注释、报错提示都以中文为主。

  三个根因（焦点、窗口类复用、消息循环不退出）里只有一个能从界面看出来；

  （方法见 §10.4 与 §9.14）。别只凭现象改代码。
